# ChatGPT × GitHub × GitLab operating contract — 25 September 2026

**Control:** PD-TRUTH-3PLANE-20260925-01

## Roles

### ChatGPT — intelligence / orchestration plane
- identify the smallest material change;
- create or interpret the immutable Truth Machine event envelope;
- distinguish fact / source content / allegation / inference / hypothesis / official outcome / contrary evidence / unresolved proof / superseded proposition;
- identify affected actor, capacity, chronology, proceeding, claim family, source and public surface;
- perform source/context/contrary-evidence/lawful-alternative analysis;
- record CHANGED or NO_CHANGE rather than restarting the whole matter.

ChatGPT does not certify deployment merely because it drafted or analysed a change.

### GitHub — rapid public/product plane
- dynamic EN/ES public readers and visualisations;
- source-safe aggregate JSON;
- event/priority-queue execution on relevant source changes and schedule;
- fast scoped release where the change is public-safe and bounded;
- exact-head Pages deployment/readback through the existing publication controller.

### GitLab — independent forensic/release assurance plane
- independently validate source pins, quotation/structure continuity, dependency reopening and private/public boundaries;
- run the same event and priority-queue controls without treating a mirror as independent evidence;
- independently build/read back the public projection;
- isolate unrelated historical CI failures rather than weakening evidential controls.

## Shared machine-readable contract

Every material change should be reducible to:

SOURCE / METHOD / CORRECTION / RELEASE EVENT
→ exact source pin(s)
→ affected node(s)
→ dependency traversal
→ affected candidate(s)
→ machine state
→ analyst state
→ release state
→ required action(s)
→ changed/no-change decision
→ scoped/full release lane
→ host-specific live verification.

`assets/data/truth-machine-events/` is the immutable change stream.
`assets/data/truth-machine-dependencies-v1.json` is the review-dependency graph.
`assets/data/truth-machine-runtime-state-v1.json` keeps machine, analyst and release state separate.

## Speed objective

Default target for a bounded, source-safe update:
1. event/change envelope;
2. deterministic source/dependency validation;
3. only affected semantic review;
4. JSON/state regeneration;
5. GitHub fast publication;
6. GitLab independent verification.

Do not rescan the entire corpus when dependencies identify a smaller affected set.

## Stop rules
- No host/model repetition increases evidential weight.
- No lexical cue becomes a truth/lie/credibility/guilt score.
- No successful build becomes a merits finding.
- No analyst conclusion becomes “live” without release evidence.
- No unrelated failed legacy control is silently erased; isolate it and choose a bounded release lane only when the current change does not depend on it.
