# Por Derecho / Sun Rock continuity and preservation propagation rule

**Control:** PD-CONTINUITY-PRESERVATION-PROPAGATION-01  
**Status:** ACTIVE / MANDATORY GOVERNANCE RULE  
**Scope:** Por Derecho, Project Sun Rock, platform-integrity incidents, linked proceedings, actors, entities, evidence registers, public derivatives and private working custody.

## 1. Governing rule

A material development is **not closed** merely because it has been recorded in one chat, one repository, one document, one email thread or one public page.

Every material development must be propagated through every materially affected canonical surface before the update is treated as complete.

Material developments include: new primary evidence; provider statements; filings or official outcomes; corrections; contradictions; status changes; identity/capacity corrections; materially relevant user clarifications; new contrary evidence; source-origin changes; privacy/publication changes; or a later event that supersedes an earlier process state.

## 2. Mandatory propagation planes

For each material development, determine which of the following planes are affected and update every affected plane:

1. **Native/private source custody** — preserve the source, exact metadata and identifiers in authorised private custody.
2. **Canonical chronology** — add the event without deleting the earlier historically accurate state.
3. **Evidence-state / proposition layer** — keep provider statement, documented fact, account-holder statement, allegation, inference, hypothesis, official finding, contrary evidence, unresolved proof and superseded proposition distinct.
4. **Machine-readable registers** — update event, claim, source, contradiction, supersession or dependency data where the architecture uses them.
5. **Public-safe derivatives** — update only the minimum publication-safe wording; never copy private message IDs, authentication links, session/IP data, reporter identities or other restricted metadata.
6. **GitHub / GitLab parity** — where a control or public surface is designated cross-host/canonical, reconcile both hosts. Host-specific operational files remain host-specific and must be labelled as such rather than blindly copied.
7. **Google Drive private control layer** — update the relevant incident/action register or control document so exact private evidence and operational status remain recoverable even when public repositories are minimised.
8. **Dependencies and cross-links** — propagate the consequence into related actors, proceedings, claims, evidence gaps, source registers and downstream pages where material.

## 3. Supersession and correction

- Never erase an earlier proposition merely because a later source changes it.
- Preserve the earlier state as historically accurate for its date, then mark the later development as correction, contradiction, supersession or new evidence.
- A supersession does not prove the opposite proposition.
- New evidence strengthens only the proposition(s) and dependencies it actually supports.
- Corrections must travel NEW→OLD and OLD→NEW through affected chronologies, registers, pages and dependencies; no correction may remain isolated in the latest document or conversation.

## 4. Identity, capacity and attribution

Person ≠ entity ≠ estate ≠ Community/CEXP ≠ administrator ≠ judge ≠ prosecutor ≠ professional firm ≠ procedural capacity.

A relationship, common source, role, payment, benefit, contact, chronology or repeated allegation does not transfer acts, knowledge, intent, participation, causation or liability.

Provider alert ≠ unauthorised act.  
Account restriction ≠ abusive reporting.  
Receipt ≠ examination.  
Registration ≠ adoption.  
Institutional possession ≠ individual knowledge.  
Repetition ≠ corroboration.  
Chronology ≠ causation.

## 5. Source bridge

A later conclusion may be upgraded only when an actual source bridge supports the upgrade. Thematic overlap or repeated wording is not independent corroboration. Where a continuity claim spans dates or proceedings, compare the actual source passages and classify the relationship as repeated, independent, corroborated, contradicted, superseded or open.

## 6. Public/private boundary

Private custody may retain exact Gmail/provider message IDs, case links, authentication-bearing URLs, security telemetry, file hashes and other sensitive provenance when lawfully held and operationally necessary.

Public repositories and pages receive only the minimised derivative needed for continuity and verification.

No public parity requirement overrides privacy, legal privilege, security or source-protection controls.

## 7. Gap-closure procedure

Before closing a material update:

1. run a host/file parity check for parity-designated controls;
2. verify the current canonical source or provider state;
3. identify missing or stale derivatives;
4. update every affected plane;
5. re-read the updated files/records;
6. record any host-specific exception or blocked dependency;
7. leave the state **OPEN_GAP** if a required propagation target is unresolved;
8. use **PARITY_COMPLETE** only after readback confirms the required targets.

If a protected branch or workflow blocks a write, use the required PR/MR/check path. A blocked direct write is not permission to bypass repository governance.

## 8. Standing application

This rule applies prospectively to every material Por Derecho / Sun Rock update. It also applies retrospectively whenever a new review reveals that a prior correction, provider statement or evidence-state change was not fully propagated.

The operational objective is anti-fragmentation with evidential discipline: one developing factual system, many legally distinct proceedings and publication surfaces, with no silent drift between them.

## Thread deletion-safety sentinel

Continuity propagation is incomplete until its thread-level deletion state is also evaluated under **PD-THREAD-SENTINEL-20260925-01**.

Every substantive Por Derecho / Sun Rock thread carries one compact state:

`🔴 RED` = deletion would cause material loss/interruption.  
`🟠 ORANGE` = preservation/deletion safety is incomplete or not yet verified.  
`🟢 GREEN` = material continuity is independently reconstructable and deletion will not interrupt a chat-bound operation.

New threads default ORANGE. Material propagation, source-custody, repo/Drive writes, automation changes, external actions and readback results must recalculate the state. The visible ChatGPT cue is a projection of the durable preservation state, not a replacement for it.

Private thread-specific source locators and active dependencies belong in the private Drive sentinel/dashboard. Public Git stores only the policy, machine semantics, validators and public-safe closeouts.
