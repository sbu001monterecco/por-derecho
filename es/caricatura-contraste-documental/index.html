Qué significa esta página

Representación crítica, no anuncio

Las piezas son deliberadamente ficticias. Pueden usar exageración, ironía, composición publicitaria y doble sentido para formular preguntas de interés público. La ficción formal no autoriza a inventar una identidad, un hotel, una cifra, una función, una relación societaria o una fuente.

Una red de relaciones, no una propiedad común

Que una persona, firma, marca, gestor, financiador, asesor, medio o activo aparezca en una misma composición no prueba propiedad común, conocimiento compartido, apoyo, coordinación ni responsabilidad. Cada relación visible necesita su propio tipo, fecha, fuente y límite.

Límite central: el signo ^ confirma identidad canónica dentro de CAEPR; no confirma la veracidad de una acusación ni convierte una relación profesional en participación en otro acto.

CONTINUIDAD OBLIGATORIA

Cada evento controlado termina con una lista de acciones

Desde este control, un evento material no queda cerrado por haber sido narrado. Debe producir un EVENT_DIGEST_ACTIONS finito que muestre qué se consultó, qué se reparó y qué sigue abierto. Las once líneas obligatorias son:

  1. Current main / routing: reconciliar `main` y los controles de arranque.
  2. Repository / GitHub digest: buscar fecha, referencia, expediente, actores, alias, fuente, activo y PR/commit pertinente.
  3. Identity ^ audit: enumerar todas las personas y entidades y comprobar ID, forma jurídica, alias, homónimos y estado ^.
  4. Source / provenance / contrary record: localizar la fuente más fuerte y conservar la prueba contraria o limitante.
  5. Chronology / causal bridges: conectar antes-evento-después sin convertir cronología en intención o causalidad.
  6. Proceeding / filing / authority: comprobar escritos presentados, anexos, registro, respuestas y uso procesal como objetos separados.
  7. Asset / money / role: separar título, equity, deuda, financiación, RIC, mandato, gestión, marca, obra, pago y beneficio.
  8. Interlink / discoverability: verificar enlaces entrantes y salientes con IDs estables.
  9. Public / private / publication: distinguir repositorio, despliegue, web viva y fuentes privadas/conectadas.
  10. Repair / validate / verify: reparar defectos seguros, ejecutar validaciones pertinentes y comprobar la ruta viva si se publica.
  11. Next actions / checkpoint: dejar una lista finita con estado y un punto de reanudación fuera del chat.

No se presume sincronización: GitHub es el soporte público de continuidad, pero no se presume que Google Drive sea un sumidero continuo, que los chats históricos estén importados, que todo Gmail/Drive citado viva en el repositorio o que un archivo temporal generado haya quedado preservado.

Fuentes, correcciones y derecho de réplica

Las piezas visuales deben permitir volver desde el titular comprimido a la fuente, el ID, la función y el límite. Una corrección no borra el artefacto previo: lo identifica, explica qué cambió y enlaza la versión vigente. Las personas y entidades aludidas pueden aportar documentación o contexto contrario para incorporarlo al registro con su estado probatorio correspondiente.
