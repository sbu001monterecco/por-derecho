# Project Sun Rock — Continuous Intelligence Protocol

**Controlling instruction for future ChatGPT research/maintenance threads**  
Updated: 15 August 2026

## Purpose

This protocol turns Gmail, Google Drive/Library, the evidential Depository and the public website into a continuously improving evidence system. It is not a prompt to repeat existing allegations. Each research cycle must search for new primary evidence, reconcile it with existing conclusions, update structured intelligence, and publish only the public-safe consequence.

## Startup sequence — mandatory

1. Read `archive/HANDOVER_MF_FISCALIA_FIRST_FRAME_JUSTICE_MAP_15AUG2026.md` in full.
2. Read this protocol.
3. Inspect `assets/data/justice-map.json` and `assets/data/fiscalia-response-correspondence.json`.
4. Inspect current `main` and recent relevant PRs before editing.
5. Search Gmail, Google Drive and the Library for the immediate question before asking the user to reconstruct facts.
6. Treat older July 2026 handovers that begin the Fiscalía chronology in 2018 as **SUPERSEDED on that point only**. Preserve them as audit history. The current structure is: 2011–12 factual prehistory → 2013 first located prosecutorial frame → 2018 role reversal → later Fiscalía/court routes.

## Search doctrine

Search by **fact, function, actor, proceeding, asset and date**, not filename alone. Search Spanish/English variants, abbreviations, spelling variants and old/new company names.

For open-web identity, corporate-role and relationship research, apply `archive/OPEN_SOURCE_INTELLIGENCE_NAMED_PERSON_ENTITY_PROTOCOL_25AUG2026.md`: log the finite corpus and queries, prefer official primary sources, preserve adverse results and treat `not located` as a bounded search result rather than proof of absence.

For Gmail, split searches into date windows: 2008–2011; 2012–2016; 2017; Jan–Jun 2018; Jul–Dec 2018; 2019–2022; 2023–2025; 2026. Read the full thread and supported attachments when authorised. Record message/thread ID, timestamp, sender, recipients, subject and attachment **only in the private evidence manifest**. The public repository records an opaque project evidence ID, a public-safe date/source class and the exact proposition supported; it must not contain provider IDs, private subjects, recipient identities or private-source bodies. A reserved declarant's personal account is acquired and reviewed only under `archive/RESERVED_DECLARANT_PRIVATE_MAILBOX_ACQUISITION_AND_CUSTODY_PROTOCOL_25AUG2026.md`.

For Drive/Library, begin with semantic search. When a relevant item is found, read the complete relevant range or inspect scanned pages visually. Never publish from a disconnected snippet. Scanned/image-only primary documents must be marked as such until visually reviewed; do not invent a text-layer conclusion.

## Evidence ledger — mandatory extraction

For every useful item record in the **private evidence ledger**:

- permanent evidence ID;
- native filename and version;
- source location (Gmail/Drive/Library/court/registry/public source);
- date/time;
- author/sender and signatory;
- recipient;
- proceeding/reference;
- native/original/copy/draft status;
- registration/receipt number;
- exact fact directly established;
- allegation contained but not independently established;
- what the item does **not** establish;
- linked people/entities;
- linked asset/right/finca;
- linked proceedings;
- earlier proposition corroborated/contradicted/superseded;
- institutional knowledge created: office and, only where proved, individual fiscal;
- confidentiality/privilege/PII status;
- public suitability: PUBLIC FACT / PUBLIC ANALYSIS / PUBLIC QUESTION / INTERNAL ONLY;
- website/depository modules affected;
- next proof step.

The public derivative of that ledger must omit native filenames where sensitive, provider/message/thread IDs, private subjects, sender/recipient identities, bodies, signatures, authentication-bearing URLs and privileged or unnecessary personal data. It may use opaque project IDs and aggregate counts. Preservation authority is not publication authority.

## Evidence levels

- **P1 PRIMARY AUTHENTIC** — signed official/court/registry/Fiscalía document.
- **P2 PRIMARY COMMUNICATION** — native email/submission with demonstrated sender/recipient.
- **P3 CONTEMPORANEOUS PROFESSIONAL RECORD** — lawyer/procurador/business record.
- **S1 SECONDARY RECONSTRUCTION** — later report accurately citing primary material.
- **A1 ALLEGATION** — assertion requiring independent verification.
- **H1 HYPOTHESIS** — analytical proposition to test.

Never allow A1/H1 to become P1 through repetition.

## Reconciliation questions for every new item

1. What exactly does this source prove?
2. What does it not prove?
3. Does it alter chronology?
4. Does it establish institutional or individual knowledge?
5. Does it contradict a Fiscalía/court/corporate proposition?
6. Does it close or open a Scope & Perimeter issue?
7. Does it affect the First Frame / role-reversal analysis?
8. Does it change requested-versus-performed investigative intensity?
9. Does it challenge a “same facts”, “civil/concursal” or “already judicialised” characterization?
10. Does it change control-before-title, beneficiary, causation or counterfactual analysis?
11. Does it require a website correction immediately?
12. Which other tracks must inherit this evidence?

## Knowledge → response → consequence discipline

For every institutional episode preserve six separate fields:

1. **KNOWN** — what receipt/record proves was before the institution.
2. **REQUESTED** — what action/diligence was requested or legally at issue.
3. **DOCUMENTED RESPONSE** — what the institution actually did.
4. **UNRESOLVED** — what remains unverified or unanswered.
5. **WHAT HAPPENED NEXT** — later factual/procedural event.
6. **CAUSAL STATUS** — routing only / temporal context / response gap / open causation question / stronger causation only if mechanism and counterfactual are proved.

Never turn “response not located” into “no response occurred”. Never turn “followed by” into “caused”.

## Public-writing rule

Translate evidence into:

**FACT → SOURCE → SIGNIFICANCE → LIMITATION → ANALYTICAL QUESTION → RESPONSE INVITED.**

Use “documented contradiction”, “no substantive response identified in the reviewed record”, “scope mismatch”, “institutional continuity”, “open causation question” and “requires independent reconciliation” where appropriate.

Do not publish personal bias, affinity, collusion, capture, deliberate shielding, knowingly false prosecution or corrupt agreement unless independent evidence reaches the required threshold.

## Named officials

Name public officials only to trace a specific documented public act. Distinguish substantive decision-maker, notification signatory, referring fiscal, court-participating fiscal, supervisory recipient and unresolved role. Never infer that a named fiscal personally knew everything institutionally held by the Ministerio Fiscal.

## Publication gate

Before publication verify:

- primary source and provenance;
- exact attribution;
- procedural status and date;
- scope of what was decided;
- “does not establish” limitation;
- privilege/PII/witness safety;
- ES/EN parity;
- internal links and evidence IDs;
- whether the public page reflects the current structured dataset;
- whether any older page now contains a superseded proposition.

## Efficient organisation

Prefer one canonical evidence object with many cross-track tags over duplicated copies. Keep documents immutable where possible; update metadata/analysis around them. Use stable IDs and explicit relationships: `submitted_to`, `signed_by`, `decided_by`, `referred_to`, `incorporated_into`, `appealed_to`, `participated_in`, `cited_by`, `contradicts`, `corroborates`, `same_asset`, `same_event`, `supersedes`.

Future ChatGPT threads should search the evidence graph/register before drafting prose. The Depository is the evidential memory; the website is a public-safe rendering of that memory.

## End-of-cycle output

Every research cycle should finish with:

1. **New verified facts**.
2. **Changed/superseded conclusions**.
3. **Contradictions opened/closed**.
4. **Proof gaps closed/new gaps**.
5. **Website/depository updates made**.
6. **Items deliberately not published and why**.
7. **Next highest-value searches**.
8. **Readiness score by track**, without inflating percentages.

Do not finish a research cycle with a prose report alone if the findings require structured intelligence or website/depository updates.
