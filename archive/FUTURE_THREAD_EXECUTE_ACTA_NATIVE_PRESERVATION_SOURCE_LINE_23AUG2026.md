## Execution sequence

### 1. Inventory every material ACTA

Build or refresh the ACTA master inventory with, for each document:

- date;
- meeting/type;
- language;
- source path/connector ID;
- native file availability;
- scan/image availability;
- text extraction/transcription status;
- page count;
- signature/stamp status;
- known duplicates/aliases;
- SHA-256 where bytes are available;
- publication status;
- authority/procedural relevance;
- privacy/redaction status.

Do not treat duplicate scans/exports as independent corroboration.

### 2. Recover best native representations

Search repository, Drive, Library and email for the best available original/native or highest-quality scan of each material ACTA. Preserve lower-quality copies only as provenance/alias records when useful.

If a native original is not available, state the best representation honestly: certified copy, scan, PDF print, photograph, transcription, extract or party-supplied copy.

### 3. Text/image parity

For every public ACTA page:

- preserve the full text where lawful and useful;
- provide or link the corresponding page images/source file where publication controls permit;
- verify headings, names, dates, offices, votes, resolutions, signatures and material numeric fields against the image;
- distinguish editorial summaries from literal transcription;
- mark illegible/uncertain text rather than guessing.

### 4. Source-line and proposition map

Create a proposition map linking every material website claim to:

- ACTA date;
- page;
- exact paragraph/line or identifiable image region;
- literal source wording;
- normalized narrative wording;
- correction/qualification if any;
- competing/contrary source if any.

Canonical identity corrections must never silently alter a quotation or literal transcription.

### 5. Authority-lineage analysis

For each ACTA, separately determine:

- who convened it;
- claimed office/authority;
- attendance/representation;
- voting basis;
- debt/vote exclusion mechanism;
- resolutions purportedly adopted;
- subsequent reliance;
- whether authority is admitted, disputed or unresolved;
- whether later title/appointment is being incorrectly projected backwards.

Majority status alone does not validate an act; minority status alone does not invalidate it. Later 2022 title does not automatically cure earlier authority defects.

### 6. Preserve good-faith correction

Do not suppress the recorded early good-faith but incorrect Community/maintenance-type invoicing practice toward some non-participating owners. Equally, do not convert that mistake into legal precedent validating later contested Community authority, debt certificates, vote exclusions or office-holder power.

### 7. Criminal/evidential boundary

Alleged falsification, usurpation, instrumentalisation, fraud or coordinated criminal conduct must remain actor-specific and evidence-led. The existence of an ACTA does not establish the truth, validity or criminal character of what it records.

Run the unitary criminal/investigative lens in parallel, but distinguish:

- literal document fact;
- procedural/legal effect;
- party allegation;
- evidential inference;
- contrary evidence;
- missing proof;
- adjudicated finding, if any.

### 8. Public privacy review

Before publishing full ACTAS/images, review for unnecessary personal data, signatures, addresses, bank data, IDs, contact details and information unrelated to the public-interest proposition. Prefer targeted redaction over narrative deletion where source transparency can be preserved safely.

### 9. Website parity and discoverability

For every published material ACTA:

- ensure EN/ES contextual parity where both language routes exist;
- ensure the source is reachable from the relevant event/actor/proceeding pages;
- ensure the narrative page links back to the ACTA source page/file;
- update sitemap/index/route registry as applicable;
- ensure visual assets are not orphaned;
- verify desktop/mobile render and links from the public edge.

### 10. Close the evidence queue

Update existing `ME-047` or the current canonical ACTA evidence queue instead of creating duplicate missing-evidence entries. Record each item as `FOUND`, `PARTIAL`, `UNRESOLVED`, `PUBLIC`, `PRIVATE`, `HASHED`, etc. only when actually supported.
