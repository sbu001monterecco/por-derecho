## 9. Legacy-PR treatment

A legacy open PR is not a current release candidate by default. For each such branch:

1. identify its claimed source and publication boundary;
2. compare every changed path with current `main`;
3. reject duplicated or superseded material;
4. revalidate primary-source status, redactions and legal/person/capacity separation;
5. transplant only the verified delta to a fresh branch;
6. run current validators and inspect the deployed route;
7. close or annotate the old PR only after the replacement lineage is controlled.

Never merge a legacy branch wholesale merely to reduce the open-PR count.
