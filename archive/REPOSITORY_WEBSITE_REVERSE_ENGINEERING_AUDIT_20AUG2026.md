# REPOSITORY ↔ WEBSITE REVERSE-ENGINEERING AUDIT

**Audit date:** 20 August 2026  
**Scope:** current Por Derecho / Project Sun Rock repository architecture, public website architecture, CAM transaction-control work, unitary-case reconstruction, public evidence graph, deployment/discoverability and deletion continuity.  
**Source hierarchy:** current `main` + canonical repository controls + direct website-source pages + externally discoverable public pages. Conversation prose does not outrank current controlled sources.

## 1. Executive conclusion

The repository has matured from a collection of dossiers into a **case operating system / institutional-memory layer**. The public website remains primarily a **reader-facing narrative publication layer**. The internal evidence architecture is presently stronger and more granular than the public evidential UX.

The strongest overall case architecture is not a single global misconduct narrative. It is a finite chain of independently testable bridges:

> **ownership / authority → debt / voting → access / control → creditor / transaction position → AC acts → Judge / LAJ acts → Registry / notarial consequences → adjudication / dación → successor title / funding → present operation**

Every bridge must be tested independently and with contrary evidence preserved.

## 3. Central explanatory proposition

The project is best explained through one foundational distinction:

> **Sun Park could be one economic hotel / operating product while legal title remained fragmented among LPB, Matkator and third parties.**

This distinction must control public and internal analysis of:

- insolvency perimeter;
- Community/CEXP authority;
- access and possession;
- works and licences;
- CAM's creditor/unit-owner position;
- investor representations;
- adjudication;
- public/private funding;
- current MYND operation.

Do not use `the hotel` as shorthand for legal ownership of every unit.

## 4. Three thresholds that must remain distinct

The repository now supports a cleaner reader model:

1. **control before title** — the 2018 material/access/operational threshold must not be rewritten as whole-hotel legal title;
2. **project/commercialisation before adjudication** — public/investor/operator project life appeared before the later formal LPB title threshold;
3. **formal title / finance / operation later** — 2022 adjudication/dación and subsequent HNT/MYND/funding layers require their own independent legal and economic analysis.

This three-threshold model should remain the principal high-level explanatory frame.

## 5. CAM transaction actor-separation rule

The controlling CAM transaction rule is:

> **CAM REQUEST / POSITION → AC RECOMMENDATION OR IMPLEMENTATION → JUDGE DECISION OR PROVED OMISSION → CONSEQUENCE**

Where applicable insert independently:

- LAJ / oficina judicial;
- Registry;
- notary.

Never collapse these into `the court/AC`.

The current controlled chain includes:

`15-Jan-2018 CAM offer → 9-Feb-2018 AC Plan/endorsement → 16-Apr-2018 judicial Plan approval + separate credit-interest act → 4-Jun-2018 bidder mechanics → 15-Jun-2018 LAJ publicity/better-offer implementation → 26-Jun-2018 judicial suspension of specified mortgaged-finca realisation → Oct-2018 AC testimony request / LAJ delivery → 28-Nov-2018 AC deed implementation → 9-Jan-2019 Registry ob-rem obstacle → AC convalidation request → 24-Oct-2019 judicial refusal of convalidation → 2021 re-tender/licitation/approval chain → 21-Feb-2022 apartment dación → later Registry/accounting/title consequences still requiring completion.`

## 6. Importance of the 2019 non-convalidation point

The 24-Oct-2019 refusal of convalidation is not merely evidence that the 2018 implementation was contested.

The important downstream questions are:

- what happened to title/registration;
- what happened to possession/control;
- what happened to the €400,000;
- how the estate accounted for it;
- what happened to the affected locales/pools and `ob rem` links;
- whether any later process expressly cured, replaced or left untouched those earlier consequences.

A later 2021/2022 approval/deed must not be treated as automatically retroactively validating the 2018 act. Cure must be proved by source and by asset/perimeter/effect.

## 7. Judge / AC / LAJ relevance

The repository's strongest institutional-accountability analysis is actor-specific.

### Judge
Require proof of:

- personally signed act;
- demonstrable hearing/receipt where relevant;
- issue actually before the Judge;
- procedural power/duty;
- absence/presence of responsive judicial act;
- material consequence.

Preserve affirmative acts that cut against an adverse theory, including suspension, competition safeguards, refusal of convalidation and later re-tender/licitation.

### Administrador Concursal
Separate:

- recommendation;
- valuation/debt analysis;
- implementation;
- reporting;
- deed execution;
- money/accounting treatment;
- post-non-convalidation action;
- later closing implementation.

### LAJ / office
Treat publication, testimony delivery, service, routing and procedural implementation as independent acts rather than judicial merits findings.

## 9. Calificación / Vista relevance

The strongest current Vista question is procedural verification, not an unsupported suppression allegation.

The public/internal analysis should ask:

- what evidence/witnesses were formally scheduled;
- who was cited/served;
- what was actually practised;
- what was accessible to participants;
- what audiovisual components exist;
- what happened to the scheduled second-day programme;
- what reached the AP;
- what Sentencia 163/2023 expressly addressed.

Earlier shorthand already required correction; the correction register must remain controlling.

## 10. Public funding / investor relevance

The same physical/project location has documented later lives involving Sun Park / MYND Yaiza, RICPE/private RIC structures, regional incentives and FEDER identification.

These layers justify a **source-and-use / title / eligible-cost / control reconciliation**.

They do **not**, merely by coexistence, establish double funding, subsidy fraud, tax fraud or misuse. Exact transaction, payment, certification, title and eligible-cost evidence must control any such theory.

## 11. Repository maturity now exceeds public evidence UX

This is the most important website-architecture finding from the current reverse-engineering pass.

Internally, the repository increasingly works as:

> **canonical proposition → status → primary evidence → contrary evidence → dependency → missing evidence → what would change the conclusion**

Publicly, many pages still communicate through independently maintained narrative prose.

The site already contains good caveats and right-of-reply/correction discipline, but a casual reader cannot consistently see the underlying proposition status beside each serious statement.

## 13. 360° route relevance

The bilingual 20-Aug 360° reverse-engineering route is a strong candidate for the principal **neutral institutional gateway** because its method does not presume that every upstream bridge is defective.

Its strongest method is:

> start from the present end-state → work backwards through indispensable bridges → reconstruct forward from origin → remove a disputed bridge and test what survives independently.

This is more robust for external institutions than beginning with an actor accusation or offence label.

## 14. Homepage capacity-separation issue

The homepage currently carries multiple roles at once:

- recovery/accountability narrative;
- Project Sun Rock hospitality/future platform;
- Por Derecho public-interest/evidence methodology.

These can coexist, but the capacities should remain more visibly separate so that:

> **recovery case ≠ Por Derecho public-interest methodology ≠ future commercial/hospitality activity.**

No evidential proposition should appear strengthened merely because it appears within a commercial/future-project context, and vice versa.

## 15. Public rhetoric / qualification placement

Some public pages already distinguish allegation, inference, unresolved fact and adverse outcome. The next UX improvement should reduce reliance on qualifications located several paragraphs away from strong rhetoric.

Preferred pattern:

> **statement + immediate status + source + qualification**

rather than:

> strong headline now + evidential limitation much later.

The repository's proposition-status system already provides the design basis.

## 16. Repository ↔ website parity must be a formal control

The current pass confirms that these are distinct states:

1. repository file exists;
2. merged to `main`;
3. Pages build succeeds;
4. route is directly readable;
5. internal navigation exposes it;
6. Updates/feed exposes it;
7. external search/indexing surfaces it.

External search did not reliably surface some 20-Aug routes despite their presence in `main`. This may be indexing/cache/discoverability lag and is **not proof of non-deployment**.

Future publication controls should record these states separately.
